# Project Recallix — Public API Reference 📘

This document provides complete technical specifications for the public interfaces, classes, methods, and configurations in **Project Recallix**.

---

## 1. Assistant Layer (`app.assistant`)

### `AssistantEngine`
The primary orchestration interface for conversing with Recallix, saving memories, and asking memory-grounded questions.

```python
from app.assistant.assistant_engine import AssistantEngine, InputType
```

#### Constructor
```python
AssistantEngine(
    retrieval_engine=None,
    llm_engine=None,
    memory_store=None,
    memory_extractor=None,
    importance_learner=None,
    memory_graph=None,
    memory_forgetter=None,
)
```
- Automatically initializes all sub-components (`RetrievalEngine`, `LLMEngine`, `MemoryStore`, `MemoryGraph`, etc.) with default configurations if not provided.

#### Methods

##### `respond(user_message: str, ...) -> dict`
Unified conversational entrypoint for processing user messages.

**Parameters**:
- `user_message` (*str*): The input text from the user. Validated against null, empty, and oversized limits.
- `top_k` (*int*, default `5`): Maximum number of memories to retrieve for question answering.
- `min_score` (*float*, default `0.0`): Minimum composite score threshold for retrieved memories.
- `semantic_threshold` (*float*, default `0.0`): Minimum cosine similarity threshold for vector search.
- `temperature` (*float*, default `0.2`): Sampling temperature for local LLM generation.
- `max_tokens` (*int*, default `500`): Maximum tokens generated by the LLM.
- `memory_relevance` (*float*, default `0.25`): Minimum relevance threshold for filtering retrieved memories.
- `include_explanations` (*bool*, default `False`): When `True`, returns explainability metadata and debug reasons.
- `fallback_to_extractive` (*bool*, default `True`): If `True`, uses extractive fallback when Ollama is unavailable.

**Returns** (*dict*):
```python
{
    "response": str,                  # Grounded assistant answer or acknowledgement
    "input_type": InputType,          # STATEMENT, QUESTION, BOTH, or NEITHER
    "extracted_memories": list[dict], # List of newly stored or updated memory records
    "memories": list[dict],           # Relevant memories passed to LLM reasoning
    "retrieved_memories": list[dict], # Raw candidate memories retrieved from search
    "intent": str | None,             # Detected query intent category
    "intent_confidence": float,       # Confidence score of intent classification
    "intent_strict": bool,            # Whether strict category filtering was applied
    "supported": bool,                # False if the question cannot be answered from memory
    "grounded": bool,                 # Whether the generated response is verified
    "grounding_details": dict,        # Detailed grounding verification results
    "llm_status": str,                # "success", "skipped_statement", or "fallback: <err>"
    "performance_metrics": dict,      # Latency breakdown (memory_ms, retrieval_ms, llm_ms, total_ms)
    "retrieval_explanations": list,   # (Optional) Component score breakdown
    "why_used": list[str],            # (Optional) Human-readable explanation strings
}
```

##### `process(user_message: str, ...) -> dict`
Direct alias to `respond()`.

##### `classify_input(user_message: str) -> InputType`
Classifies input string into `InputType.STATEMENT`, `InputType.QUESTION`, `InputType.BOTH`, or `InputType.NEITHER`.

##### `save_extracted_memories(extracted_memories, temporal_state=None) -> list[dict]`
Validates, sanitizes, vectorizes, and saves extracted memory triplets using lifecycle update semantics.

##### `close()`
Gracefully flushes sessions and releases database and graph resources.

## 2. Memory Layer (`app.memory`)

### `MemoryStore`
Database access layer managing SQLite transactions and dense vector storage.

```python
from app.memory.memory_store import MemoryStore
```

#### Key Methods
- `save_memory_with_semantics(subject, relation, value, category="GENERAL", importance=5, embedding=None, temporal_state="PRESENT") -> tuple[Memory, str, dict]`:
  Saves a memory applying conflict detection and superseding rules. Returns `(memory_obj, status, metadata)`.
- `get_all_memories() -> list[Memory]`: Retrieves all memory records (active and archived).
- `get_active_memories() -> list[Memory]`: Retrieves all memories where `active == True`.
- `get_memory_by_id(memory_id: int) -> Optional[Memory]`: Looks up a specific memory by primary key.
- `archive_memory(memory_id: int, reason: str = None) -> bool`: Soft-deletes a memory (`active = False`) with archival metadata.
- `restore_memory(memory_id: int, overwrite_conflict: bool = False) -> tuple[Memory, str, dict]`: Restores an archived memory.

---

### `MemoryGraph`
Directed knowledge graph managing entity relations and multi-hop traversals.

```python
from app.memory.graph import MemoryGraph
```

#### Key Methods
- `add_edge(source: str, relation: str, target: str, category="GENERAL", weight=1.0, memory_id=None)`: Adds a directed relationship edge.
- `get_neighbors(node: str, depth=1) -> set[str]`: Returns neighboring entity nodes up to specified depth.
- `find_paths(source: str, target: str, max_depth=3) -> list[list[str]]`: Discovers multi-hop paths between two entities.
- `calculate_proximity(entity1: str, entity2: str) -> float`: Computes normalized proximity score ($1 / (1 + \text{path\_length})$).
- `clear()`: Empties in-memory graph nodes and edges.

---

### `ImportanceLearner`
Reinforcement learning component for memory relevance.

```python
from app.memory.importance_learning import ImportanceLearner
```

#### Key Methods
- `calculate_effective_importance(memory: Memory) -> float`: Returns dynamic importance computed from base importance, access frequency, helpful count, and reinforcement score.
- `apply_retrieval_feedback(retrieved_memories: list[dict], supported_values: list[str])`: Boosts memories that supported grounded answers (+0.5) and penalizes unhelpful noise.

---

### `MemoryForgetter`
Controlled memory forgetting and dormancy manager.

```python
from app.memory.forgetting import MemoryForgetter
```

#### Key Methods
- `evaluate_for_forgetting(memory: Memory) -> tuple[bool, str]`: Checks if a memory should be archived based on dormancy and importance.
- `forget_dormant_memories() -> list[dict]`: Archives all qualifying dormant memories while respecting protection rules.

## 3. Retrieval Layer (`app.retrieval`)

### `RetrievalEngine` & `AdvancedRetrievalEngine`
Performs hybrid multi-signal retrieval over stored memories.

```python
from app.retrieval.retrieval_engine import RetrievalEngine
from app.retrieval.advanced_retrieval import AdvancedRetrievalEngine
```

#### Key Methods
- `search(query: str, top_k=5, min_score=0.0, semantic_threshold=0.0) -> list[dict]`:
  Searches active memories using hybrid multi-signal ranking.
- `analyze_query_intent(query: str) -> dict`:
  Detects query category intent (`PROJECT`, `EDUCATION`, `SKILL`, `GOAL`, `LOCATION`, `PREFERENCE`), intent confidence, and normalized query form.

## 4. LLM Layer (`app.llm`)

### `LLMEngine`
Handles local LLM inference via Ollama with strict grounding prompts.

```python
from app.llm.llm_engine import LLMEngine
```

#### Key Methods
- `is_available() -> bool`: Returns `True` if the local Ollama instance is reachable.
- `generate_with_memories(user_message: str, memories: list[dict], temperature=0.2, max_tokens=500) -> str`:
  Constructs a grounded prompt and generates an answer strictly constrained by retrieved memories.
- `build_memory_context(memories: list[dict]) -> str`: Formats retrieved memories into bulleted text context.
- `verify_answer_grounding(response: str, memories: list[dict]) -> dict`:
  Validates that response claims are supported by memory values. Returns `grounded`, `supported_values`, and `grounding_score`.

### `LatencyTracker` (`app.utils.metrics`)
Sub-millisecond execution timer for pipeline profiling:

```python
from app.utils.metrics import LatencyTracker

tracker = LatencyTracker()
with tracker.timer("stage_name"):
    do_work()

metrics = tracker.get_metrics()
# -> {"stage_name": 1.25, "total_ms": 1.25}
```

### Validators (`app.utils.validators`)
- `sanitize_text(text: str) -> str`: Strips control characters and trims whitespace.
- `validate_memory_content(subject, relation, value, category=None, max_length=None) -> dict`: Validates and sanitizes memory fields.
- `validate_embedding_vector(vector_bytes: bytes, expected_dim=384) -> np.ndarray`: Validates size, checks for NaN/Inf/zero magnitude.
- `validate_user_query(query: str, max_length=None) -> str`: Validates query string against empty and oversized inputs.

---

### Custom Exceptions (`app.utils.exceptions`)
- `RecallixError`: Base class for all domain exceptions.
  - `DatabaseError`: SQLite and persistence issues.
  - `EmbeddingError`: Vector computation or deserialization errors.
  - `LLMError`: Ollama communication or generation failures.
  - `MemoryValidationError`: Malformed memory content (inherits from `ValueError`).
  - `InvalidQueryError`: Invalid or empty user queries (inherits from `ValueError`).
